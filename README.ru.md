# NFO Updater

Поддерживает в актуальном состоянии рейтинги в NFO-файлах Kodi.

## Возможности

- **Шесть источников рейтингов** — IMDb, TMDb, Rotten Tomatoes (критики и зрители), Trakt и Metacritic. Каждый включается и выключается отдельно.
- **Фильмы и сериалы** — раздельная обработка: фильмы, сериалы и отдельные эпизоды.
- **Стандарт Kodi на выходе** — стандартные записи внутри `<ratings>`. Никаких "плоских" тегов и собственных расширений.
- **Бережное обращение с данными** — рейтинги, которых нет в списке выше, остаются в исходном файле неизменными.
- **Резервные копии** — оригиналы всех изменённых файлов можно архивировать на каждом проходе.
- **Работа с квотами** — несколько ключей на сервис используются по очереди,
  суточный счётчик ведётся отдельно для каждого ключа.
- **Исправление метаданных** — добавляет современные записи `<uniqueid>` там, где есть
  только устаревшие идентификаторы, и заполняет отсутствующую дату `<premiered>`.
- **Порядок съёмочной группы** — переносит `<credits>` и `<director>` под список актёров для сервера Emby.
- **Обновление медиатеки** — опционально запускает сканирование медиатеки Emby, Jellyfin или Plex, если что-то изменилось.
- **Работа по расписанию** — резидентная работа с расписанием в стиле cron.
- **Мастер настройки** — помогает в базовой настройке, проверяет ключи/токены и адреса серверов.
- **Журнал каждого прохода** — отдельный файл на проход со сводкой в конце.

## Установка и настройка

NFO Updater может быть установлен на систему Linux или как [Docker-контейнер](#docker).

### Debian / Ubuntu (рекомендуется)

Понадобится 64-битная x86 версия системы, `curl` или `wget`, `tar`, `sha256sum`.<br>
`Systemd` нужен, только если медиатеку требуется обновлять по расписанию.

Установка:

```sh
wget -qO- https://raw.githubusercontent.com/alexls74/nfo_updater/main/nfo_updater.sh | sh -s -- install
```

или:

```sh
curl -fsSL https://raw.githubusercontent.com/alexls74/nfo_updater/main/nfo_updater.sh | sh -s -- install
```

> Запускать нужно от пользователя, а **не** через `sudo`. Настройки принадлежат текущему пользователю; под `sudo` они попадут в домашний каталог root. Пароль установщик спросит сам и только на тех шагах, где он действительно нужен.

Установщик скачивает релиз, сверяет контрольную сумму и передаёт управление мастеру настройки. Мастер спрашивает:

- нужно ли обновлять медиатеку по расписанию и как часто;
- где хранить пользовательские данные;
- каталоги, в которых лежат фильмы и сериалы;
- ключи API (см. [Настройка](#настройка) — подготовьте их заранее);
- настройки медиасерверов, если они нужны.

Ответ *да* на вопрос о расписании — установщик зарегистрирует systemd-службу; ответ *нет* — вы получите программу, которую запускаете сами. До последнего вопроса на диск не пишется ничего, поэтому выход на полпути ничего не меняет.

#### Команды установщика

Тот же скрипт поддерживает все необходимые служебные команды. Запускайте его, заменив `install` на любую из нижеследующих команд:

| Команда | Что делает |
| --- | --- |
| *(нет)* | Показать меню. |
| `install` | Скачать, настроить и установить. |
| `update` | Обновить до последнего релиза. `update x.x.x` — до конкретного релиза. |
| `configure` | Пройти мастер настройки заново. |
| `service on` | Зарегистрировать службу для уже установленной программы. |
| `service off` | Удалить службу. Программа и её настройки остаются. |
| `status` | Показать, что установлено, где и что делает служба. |
| `remove` | Удалить программу и службу. |
| `help` | Показать список команд. |

`update` заменяет исполняемый файл на месте, в какой бы каталог он ни был установлен.<br>
`remove` не удаляет настройки, базу, журналы и резервные копии — см. [расположение файлов](#расположение), если нужно удалить.

#### Настройка

Мастер установки задаёт обязательные параметры. Ниже описаны все настройки `config.conf`.

#### Ключи API

Настроить нужно все сервисы. Каждый ключ проверяется в начале каждого прохода, поэтому истёкший или отозванный ключ сразу попадает в журнал.

| Сервис | Где получить ключ | Бесплатный лимит | Параметр |
| --- | --- | --- | --- |
| OMDb | [omdbapi.com/apikey.aspx](https://www.omdbapi.com/apikey.aspx) | 1000 запросов в сутки на ключ | `OMDB_API_KEYS` |
| MDBList | [mdblist.com/preferences](https://mdblist.com/preferences/) | 1000 запросов в сутки на ключ | `MDBLIST_API_KEYS` |
| TMDb | [themoviedb.org/settings/api](https://www.themoviedb.org/settings/api) | без суточного лимита | `TMDB_API_KEY` |

> **TMDb.** Нужно значение, подписанное **API Key**, — 32 символа, цифры и строчные `a`–`f`. **API Read Access Token** с той же страницы относится к другой схеме аутентификации и будет отвергнут.

OMDb и MDBList принимают несколько ключей через запятую без пробелов. Они используются по очереди, по мере исчерпания суточной квоты каждого.

#### Параметры

| Параметр | Для чего |
| --- | --- |
| `MOVIES_PATH`, `TVSHOWS_PATH` | Где лежит медиатека. Можно указать несколько каталогов — через запятую. |
| `IMDB_RATING`, `TMDB_RATING`, `POPCORN_RATING`, `TRAKT_RATING`, `TOMATOES_RATING`, `METACRITIC_RATING` | Какие рейтинги записывать. Каждый — `yes` или `no`. Переключённый в `no` рейтинг удаляется из файлов на следующем проходе. Оставленный в `yes` сохраняет прежнее значение, если получить новое не удалось. |
| `DEFAULT_RATING` | Какой из включённых рейтингов считается для записи главным и помечается в файле как `default="true"`. Это обязательный параметр по стандарту Kodi. По умолчанию `imdb`. |
| `CREW_ORDER_FIX` | Перенести `<credits>` и `<director>` под список актёров. Изменяется только порядок в файле, ничего не добавляется и не удаляется. Emby в точности следует порядку в файле, поэтому файл, где съёмочная группа стоит выше актёров, так и показывается. |
| `SCHEDULE` | Расписание запусков сканирования медиатеки. Cron-выражение. Пустое значение — каждый понедельник в 03:00. |
| `BACKUP_ENABLED`, `BACKUP_DIR`, `BACKUP_LIMIT` | Резервные копии оригиналов и сколько архивов хранить в каждой категории. |
| `LOG_ENABLED`, `LOG_VERBOSE`, `LOG_DIR`, `LOG_LIMIT` | Файлы журнала и лимит хранения. |
| `DATABASE_PATH` | Где хранится кэш рейтингов. |
| `EMBY_*`, `JELLYFIN_*`, `PLEX_*` | Необязательное: запустить сканирование медиатеки, если что-то изменилось. |

Что стоит знать до правки файла:

- **Каждый путь должен быть абсолютным и записанным полностью.** Относительный путь NFO Updater не раскрывает, поэтому `~/some_path/logs` отвергается. Следует указывать полный путь  `/home/yourname/some_path/logs`.
- Пути к фильмам не должны пересекаться с путями к сериалам, и ни один путь не должен лежать внутри другого. Символические ссылки нельзя использовать.
- Оставьте `DATABASE_PATH`, `LOG_DIR` и `BACKUP_DIR` пустыми, чтобы всё находилось в одном каталоге внутри вашей домашней папки.
- Переключённый в `no` рейтинг удаляется из файлов на следующем проходе. Оставленный в `yes` сохраняет прежнее значение, если получить новое не удалось. Рейтинги, записанные другими программами, не трогаются ни в том, ни в другом случае.
- Включить медиасервер — значит заполнить и адрес, и ключ, иначе конфигурация отвергается. Адрес должен быть доступен там, где работает NFO Updater.

Резервные копии — zip-архивы, по одному на проход, отдельно для фильмов и сериалов:

***backups/Movies/2026-08-10_03-00-11.zip<br>
backups/TVShows/2026-08-10_03-00-11.zip***

В архив попадают только те файлы, которые действительно изменились, каждый — со своим полным путём. Самые старые архивы сверх `BACKUP_LIMIT` удаляются по мере появления новых, счёт ведётся по категориям.

#### Применение изменений

Если служба работает, новые настройки будут приняты командой:

```sh
sudo systemctl reload nfo_updater
```

> Именно `reload`, а не `restart`.

Если в этот момент идёт сканирование/обработка, новая конфигурация применится сразу после окончания. Если конфигурация содержит ошибки, она не будет применена, соответствующая запись попадёт в журнал, а в силе остаётся прежняя.

#### Использование

**Как служба**

NFO Updater работает как systemd-служба и не требует обслуживания.
Команды, которые могут понадобиться:

```sh
systemctl status nfo_updater            # текущее стотяние
journalctl -u nfo_updater -f            # события службы
systemctl kill -s USR1 nfo_updater      # запустить проход вне расписания
sudo systemctl reload nfo_updater       # применить файл конфигурации
sudo systemctl stop nfo_updater         # остановить
```

Идущее сканирование/обработка никогда не обрывается: при остановке программа дописывает файл, над которым работает, упаковывает резервные копии и только потом выходит. systemd ждёт этого до пяти минут.

**Разовый запуск**

Без расписания. Запустите программу сами:

```sh
nfo_updater
```

Она делает один проход по медиатеке и завершается. Одновременно работает только один экземпляр: запущенный во время фоновой работы, он сообщает об этом и выходит, ничего не тронув. Доступны следующие флаги:

| Флаг | Что делает |
| --- | --- |
| *(нет)* | Один проход по медиатеке. |
| `--setup` | Мастер настройки. Запускать повторно можно в любой момент. |
| `-d` | Режим резидентной работы: оставаться в памяти и запускать проход по расписанию. |
| `-v` | Показать версию и пути. |
| `--config PATH` | Использовать другой файл конфигурации. По умолчанию `~/.config/nfo_updater/config.conf` |
| `-h`, `--help` | Полная справка, включая коды возврата. |

#### Расположение

| Что | Путь |
| --- | --- |
| Конфигурация | `~/.config/nfo_updater/config.conf` |
| Кэш рейтингов | `~/.local/share/nfo_updater/database.db` |
| Журналы | `~/.local/share/nfo_updater/logs/` |
| Резервные копии | `~/.local/share/nfo_updater/backups/` |
| Программа | `/usr/local/bin/nfo_updater`, либо `~/.local/bin/nfo_updater` при `--user` |
| Файл службы | `/etc/systemd/system/nfo_updater.service` |

**Конфигурацию** можно перенаправить флагом `--config`.<br>
**Кэш рейтингов**, **журналы** и **резервные копиям** — можно задать свои пути в файле конфигурации.

### Docker

Понадобится 64-битная x86 Linux OS, Docker Engine и плагином Compose.

Скачайте два файла:

```sh
mkdir nfo_updater && cd nfo_updater
wget -O docker-compose.yml https://raw.githubusercontent.com/alexls74/nfo_updater/main/docker-compose.yml
wget -O .env https://raw.githubusercontent.com/alexls74/nfo_updater/main/.env
chmod 600 .env
```

`.env` — файл конфигурации.<br>[Ключи API](#ключи-api) заполнять обязательно. Остальное — по желанию.

Медиатека в `.env` не настраивается. Пути к папкам с nfo-файлами указываются в `docker-compose.yml`:

```yaml
    volumes:
      ...
      - /mnt/media/movies:/movies
      - /mnt/media/tvshows:/tvshows
```

Замените левую часть каждой строки своими путями. Правая часть фиксирована: `/movies` и `/tvshows` — это то, что использует NFO Updater в контейнере.

Можно использовать несколько папок каждой категории исходных данных. Но они должны подключаться как вложенные папки внутри основной.<br>Пример:

```yaml
      - /mnt/disk1/films:/movies/films
      - /mnt/disk2/oldies:/movies/oldies
      - /nas/serials:/tvshows/serials
      - /mnt/disk2/anime:/tvshows/anime
```

Они могут находится на разных дисках. Связывают их именно эти две точки монтирования. Всё, что находится внутри `/movies` и `/tvshows` контейнера, обрабатывается рекурсивно.
> Неверный путь слева от двоеточия — это ошибка, которую Docker не может диагностировать. Он создаст пустую папку. NFO Updater предупредит о пустой точке монтирования в журнале и откажется запускаться.

Запуск контейнера:

```sh
docker compose up -d
```

На этом установка закончена. NFO Updater будет работать по расписанию.

#### Команды

| Команда | Что делает |
| --- | --- |
| `docker compose logs -f` | Проверка журнала. |
| `docker compose kill -s SIGUSR1 nfo_updater` | Запустить прямо сейчас, вне расписания. |
| `docker compose up -d` | Применить изменения, внесённые в `.env`. |
| `docker compose stop` | Остановить, дождавшись конца текущей работы. |
| `docker compose pull && docker compose up -d` | Обновить до актуальной версии. |

Запущенная работа не обрывается: при остановке дописывается текущий файл, создаются резервные копии и только потом выход.

> После правки `.env` необходим `up -d`, а не `restart`. Контейнер сохраняет окружение с которым был создан, поэтому после перезапуска продолжил бы работать с прежними настройками. `up -d` пересоздаёт контейнер.

#### Запуск вручную

Запустить работу NFO Updater вне расписания можно двумя способами, и это не одно и то же.

```sh
docker compose kill -s SIGUSR1 nfo_updater
```

Запускает работу, как если бы она запустилась по расписанию. В терминале ничего не отображается, данные фиксируются в журнале.

```sh
docker exec -it nfo_updater nfo_updater
```

Запускает отдельный одиночный проход и выводит данные в терминал. Это удобно в первый раз или при диагностировании проблемы.

#### Расположение файлов

| Что | На этой машине | Внутри контейнера |
| --- | --- | --- |
| Настройки | `./.env` | — |
| Кэш рейтингов | `./data/database.db` | `/data/database.db` |
| Журналы | `./data/logs/` | `/data/logs/` |
| Резервные копии | `./data/backups/` | `/data/backups/` |

Файл конфигурации собирается из `.env` и остаётся внутри контейнера. 

`data` создаётся при первом старте.

От обычной установки отличаются две вещи. И обе из-за точек монтирования:

- **Пути внутри архива с резервными копиями — это пути контейнера.** Файл, смонтированный в `/movies/films`, хранится под этим именем, а не под своим путём.
- **Адрес медиасервера должен быть доступен изнутри контейнера.** `localhost`  — это сам контейнер, поэтому для сервера на том же компьютере указывается адрес в сети.
